# ADR-0002: ELFの受け渡し方式

- 状態: 提案中（技術検証後に確定）
- 日付: 2026-10-09

## 背景

ブラウザからのELFアップロードを希望している。一方、利用者が知り合いに限定される初期段階では厳格なファイルサニタイズは想定していない。また、アップロードの実装コストが高い場合は、利用者がWSL内の指定ディレクトリにELFを配置する方式でもよい。

## 選択肢

### A. ブラウザからアップロード

利点:

- WindowsブラウザとWSL側のパス差を隠せる。
- 操作が一般的で初心者にも分かりやすい。
- 将来のWeb版と操作モデルを合わせやすい。

注意点:

- 受け取り、サイズ制限、保存先、セッションごとのファイル管理、削除が必要。
- アップロードしたELFは実際に実行されるので、実行リスクは別途説明・管理する。

### B. WSL内ディレクトリから選択

利点:

- ファイル転送機能を省略できる。
- 既にあるpwn環境や問題ディレクトリを使いやすい可能性がある。

注意点:

- 利用者がWSL内のパスを把握する必要がある。
- Webバックエンドがアクセスできる範囲を決める必要がある。
- Windows側のファイル選択ダイアログからWSLのパスを直接扱えると仮定できない。

## 推奨

まずAを試す。通常のWebバックエンドでファイル受け取りと保存を実装すること自体は、初期版を阻害するほどの大きな機能にはなりにくいと考える。ただし、技術検証では実際のコード量・テスト負担を確認し、予想外に複雑ならBに切り替えてよい。

## 最低限の安全上の扱い

初期版で高度なサニタイズやマルチテナント隔離を導入する必要はない。一方、保存名をバックエンドで生成する、サイズを制限する、ファイルを専用作業領域に置く、検査合格を無害性の保証としない、という基本措置は採用する。

## 確定条件

`docs/experiments/` に小さなPoC結果を記録したうえで、ユーザーが方式を承認する。
