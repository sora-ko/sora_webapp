# 未決定事項と確認リスト

AIはここを、未決定事項の唯一の一覧として維持する。結論が決まった項目は、関連文書と `docs/decisions/` を更新し、状態を変更する。

## 優先度 P0 — 実装着手前に小さく検証する

### Q-001: ELFの受け渡し方法

- 候補A: ブラウザからアップロードし、バックエンドの管理ディレクトリへ保存する。
- 候補B: 利用者がWSL内の所定ディレクトリへ置き、GUIでファイルを選ぶ。
- 方向性: ブラウザアップロードを第一候補とする。一般的なWebフレームワークでは比較的小さな機能であり、WindowsブラウザとWSLのパス差をユーザーに意識させずに済むため。ただし、実装コストが想定より大きければディレクトリ方式へ切り替える。
- 検証: ファイルを受け取り、ランダム名の作業領域に保存し、GDBでロードできる最小PoCを作る。
- 決定者: ユーザー。PoCの結果を見て確定する。

### Q-002: 対象プロセスI/OとGDB/MIの分離

- 問題: GDBの制御チャネルと、デバッグ対象のstdin/stdout/stderrを分離する必要がある。
- pwnで重要な点: 改行を付けるか、EOFを送るか、バイナリのNULバイトを含めるか、TTYかパイプかによって対象プログラムの挙動が変わる。
- 検証: `read()` を使うサンプル、`scanf()` を使うサンプル、入力を待つサンプルで、GUI操作とGDBの操作が干渉しないことを試す。
- 成果: Process I/Oの方式、対象とする入力形式、制約を記録する。

### Q-003: GDB/MIと非同期状態管理

- 問題: GDB/MIのコマンド応答と、実行停止・終了などの非同期通知を整合させる必要がある。
- 検証: 起動、ブレークポイント、run、interrupt、step、SIGSEGV、終了を順に扱い、状態が破綻しないことを確認する。

### Q-004: WSLの起動・ブラウザ接続

- 問題: バックエンドをWSLで起動し、Windows側ブラウザからlocalhost経由で利用する開発体験を検証する。
- 検証: 新規環境に近い手順でインストール、起動、アクセス、停止まで実施する。必要な設定をREADMEに記録する。

## 優先度 P1 — MVPの詳細を確定する

### Q-005: ELFの依存ライブラリ

初期版ではELF単体を指定するが、動的リンク先のライブラリが環境に存在しない場合がある。初期版ではエラーを分かりやすく表示するだけにするか、任意の実行ディレクトリも提供できるようにするかを決める。pwninitによる解決は後回し。

### Q-006: プログラム引数と環境変数

pwn問題によっては引数や環境変数が必要になる。初期版で設定UIを用意するか、次版に回すかを決める。任意シェルコマンドの入力とは区別する。

### Q-007: ASLRの扱い

デバッグ環境でASLRを変更するか、GDBの標準動作に任せるかを決める。利用者に明示せず設定を変更しない。再現性と実環境に近い挙動のどちらを初期版で優先するか検討する。

### Q-008: ブレークポイントUI

初期版でアドレス指定を必須にする。シンボル名指定やソース行指定は、情報がある場合だけ支援する方針でよいか確定する。

### Q-009: スタックの行表示

表示単位（byte / 4-byte / 8-byte）、エンディアン、ASCII表示、ポインタらしい値の注釈、スクロール単位、更新前後の差分などを決める。生の値と推定された意味を別に表示する。

### Q-010: 入力ペイロードUI

最終目標でオーバーフローを扱うため、通常テキストに加え、16進数やエスケープ表現からバイト列を送れる必要がある可能性が高い。テキスト／改行付きテキスト／16進バイト列／EOFの扱いを検討する。
