# pwn Debug GUI — プロジェクト文書

このリポジトリは、pwn初心者向けのローカル実行型デバッグGUIを、AI支援開発で継続的に構築するための設計文書をまとめたものです。

## プロジェクトの要約

利用者自身のUbuntu / WSL環境でコンパイル済みx86-64 Linux ELFをデバッグし、レジスタ・逆アセンブル・メモリ・スタックの状態をWeb GUIで確認できるようにします。6か月後の目標は、意図的に脆弱なサンプルプログラムでバッファオーバーフローを発生させ、スタック上の値がどのように変化したかを利用者がGUIから理解できることです。

AIエージェントは作業前に `AGENTS.md` を読み、関連する設計文書を確認してください。

## 決定事項の扱い

各文書では、内容を次の区分で扱います。

- **合意済み**: 会話でユーザーが明示した方針
- **推奨案**: 設計上の提案。ユーザーが承認するまでは決定事項ではない
- **未決定**: 判断材料や検証が不足している事項
- **対象外（初期版）**: 将来は検討できるが、初期版では実装しない事項

AIは「推奨案」をユーザーの承認なく「合意済み」に変更してはいけません。決定が変わった場合は、関連文書と決定記録を同時に更新してください。

## 現時点の重要方針

- ローカル実行型を初期版の前提とする。バックエンドは利用者自身のUbuntu / WSLで動かす。
- 対象はx86-64 Linuxのコンパイル済みELF。
- GDBを基本デバッガーとして扱い、pwndbgはオプションの拡張とする。
- 初期版では基本的なデバッグを実現し、6か月後にはオーバーフローとスタックの変化をGUIで追えることを目指す。
- AIが実装を進められる明確な責務分担、検証可能性、安全設計を重視する。
- ELFのブラウザアップロードは候補。ローカルディレクトリ指定方式と比較し、簡単な技術検証で確定する。
- `pwninit`、ライブラリ取得、patchファイル生成などの環境自動構築は初期版の対象外。
