# 動作確認用CSV

更新日: 2026-10-28。以下のCSV3点は個人情報がないことを確認してGit管理する。クローン後にそのまま手動確認・自動テストへ使用でき、ZIPの展開は不要である。[初回起動手順](../docs/handoff.md)を参照する。その他のCSVは引き続きGit対象外とし、実在する学生CSVを代用してテストへ登録しない。

`first-year-sample.csv`は、1年生として画面の動作を確認するためのUTF-8 CSVである。氏名、在籍番号、教員、開講番号、成績は架空である。専門科目と必修指定科目には分類確認用に公式科目名を使うが、実在する学生の情報は含まない。

画面からアップロードしたときの期待結果:

- 学年: 1年
- 取得済み: 34単位
- 表示要件: 第2年次進級条件、卒業資格条件
- 第2年次進級のD科目を除く単位: 32 / 32単位
- 指定5科目群: 4 / 4単位
- 在学期間: CSVの学年を使って1 / 1年
- 第2年次進級の総合判定: `satisfied`
- 新潟大学個性化科目2単位: 教養の「人文社会・教育科学または新潟大学個性化科目（選択必修）」へ算入
- 工学リテラシー入門(架空分野): 分野名を区別せず大学学習法の必修2単位へ算入
- 自然系共通専門基礎10＋自然科学3: 選択必修の対象は13単位。そのうち10単位を充当し、残り3単位を教養の選択へ算入
- 卒業資格の総合判定: 在学期間・専門単位・必修科目等が不足するため`not_satisfied`

## 卒業条件を満たす架空CSV

手動確認には[`graduation-sample-original-format.csv`](graduation-sample-original-format.csv)を使用する。利用者提供CSVの構造だけを参照し、次の形式を再現している。提供された学生情報・成績は転記していない。

- 文字コード: CP932（BOMなし）
- 改行コード: CRLF
- 1行目: 学生氏名・在籍番号、2行目: 学生所属・学年、3行目: 年度・学期、4行目: 空行（19個の空欄）
- 5行目: 元CSVと同じ見出し・列順の19列、6行目以降: 科目行。前置きも含め全行19列
- 氏名「架空 卒業生」、在籍番号「T00000000」、学年「4年」。2025年度入学者の4年次末を想定し、年度・学期は2028年度第2学期の架空値

既存の`graduation-sample.csv`は、同じ単位・科目構成を持つ簡略版（UTF-8、前置き1行、9列）として保持する。どちらも公式科目名に架空の開講番号・成績を付けており、期待結果は次のとおり。

- 取得済み124単位（専門88、教養36）
- 専門系必修16科目すべて修得
- 専門または教養の超過単位6
- 卒業総合判定`satisfied`

教養の一部には区分ごとの合計をまとめた架空科目（10単位など）を使っており、実在する履修計画を表すものではない。得点・評語・GP・修得年度・教員・報告日もすべて動作確認用の架空値である。

卒業資格条件内の「専門系の個別必修科目」から科目別結果を開ける。`プログラミングＡⅡ`の行を別コードの`プログラミングＡⅠ`へ変えると、合計124単位とA合計27単位を保ってもＡⅡが未修得となり、卒業総合は`not_satisfied`になる。

Dockerで確認する場合は、プロジェクト直下で`docker compose up --build`を実行し、`http://localhost:8000`を開く。1年生の進級確認には`first-year-sample.csv`、元CSV形式での卒業確認には`graduation-sample-original-format.csv`を選択する。
