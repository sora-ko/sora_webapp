# 教養推薦用の簡易JSON

利用用JSONは `data/recommendations/2026/liberal-catalog.json` の1つ。2026-10-27の利用者指定により学年による絞り込みを外した。全件版1,228開講から、条件に合う309開講を経て、時間枠と大区分を保つ代表63開講へ削減した。約22KB。[候補APIと参考UI](recommendation-api.md)の指定枠検索・全曜限の重複除外に加え、[単位照合の探索API](recommendation-search-api.md)でも同じカタログを使う。

## 1. 1科目6項目

カタログは `schema_version: 3`。全体に `academic_year`、`profile_id`、`courses` を持つ。対象学年は持たない。科目ごとの年度・出典・IDの繰返しや、空のシラバス概要、監査情報は持たない。

| 科目の項目 | 内容 |
| --- | --- |
| `course_code` | 開講番号。同名でも別番号は別科目 |
| `name` | 表示と、必修名との照合に必要な科目名 |
| `credits` | 正の単位数 |
| `category` | 要件計算に使う「大区分（細区分）」の文字列。既存の分類器で読み取れる |
| `terms` | 開講するタームの配列 |
| `schedule` | 曜日・時限の組。曜日は月=1〜金=5。全てのタームに同じ曜限が適用される |

例は架空値である。

```json
{
  "schema_version": 3,
  "academic_year": 2026,
  "profile_id": "niigata-engineering-sis-2025-v1",
  "courses": [
    {
      "course_code": "263G9991",
      "name": "架空教養科目",
      "credits": 2,
      "category": "自然科学（架空区分）",
      "terms": [3],
      "schedule": [{"weekday": 1, "period": 3}, {"weekday": 4, "period": 3}]
    }
  ]
}
```

複数曜限の授業は全枠を保持し、片方だけで推薦しない。タームによって曜限が違う場合はこの形式へ無理に畳まず、生成を止める。主聴講対象の学部等の条件は生成時に確認し、利用時は年度・プロファイルを照合する。単純な学年指定は利用者方針により候補の除外に使わず、同じファイルを全学年で共用する。これは履修資格の保証ではない。

## 2. 科目を減らす条件

- 公式表でGコードとして確認でき、分類・単位・期間・曜限が明確な科目だけを使う。
- 条件の解釈を単純にするため、「全学部」と単純な学年指定の科目に絞る。工学部だけの授業も、「自然系学部・他」も採用しない。
- 優先対象・再履修・分野・クラス等の追加条件がある記載は、履修できると推測せず採用を保留する。学部限定ではなくても、条件を読み切れないものは含めない。
- 学年による候補の変更は行わない。留学生向けは除外する。
- 開講番号0・集中・不明曜限・オンデマンドを除く既存方針を維持する。0でも通常授業の例があるが、この変更では方針を変えない。
- 全曜限が月〜金・1〜5限に収まる科目を使う。土日・6限以降を持つ科目を途中で切り落とさない。

その309開講から、まだ保持していない曜限とタームごとの大区分を多く補えるものを順に採用し、不要な重複を落として63開講にした。同点は開講番号順とし、入力順によって結果を変えない。数学的な最小件数や推薦順位を示すものではない。

削減後も元候補の85枠と、各タームに存在する大区分8種の候補を保持する。曜日・時限ごとの全区分、全ての語学の種類、全ての科目名を保持する保証はない。より細かな選択肢が必要になった場合は、保管した原表から再生成できる。

## 3. 各ターム・1〜5限の調査

曜日をまとめた「ターム×時限」の20通りには、全て1件以上の候補がある。一方、月〜金まで分けた100枠全てには候補がない。

| ターム | 確認できた枠 /25 |
| --- | ---: |
| 1 | 24 |
| 2 | 23 |
| 3 | 19 |
| 4 | 19 |
| 合計 | 85 /100 |

309開講は単純な主聴講対象の学年を絞らない集合であり、全ての学年が履修できるという意味ではない。候補のない15枠の一覧と曜日別の候補数は、生成した `data/recommendations/2026/README.md` に記載する。

この結果は資料と現行の除外方針で確認できた範囲である。「候補0」は授業の不存在や履修不許可を意味しない。履修中科目との重複、修得済み科目の除外、不足枠への効果は学生ごとの推薦時に別途確認する。

## 4. 出典は別管理

科目ごとの推薦JSONから出典を外してよい。誤分類の修正や年度更新に必要な元資料との対応は、次の場所へまとめて保持する。

- 年度・資料時点・公式URL・対象設定：`catalog_sources/niigata-2026.json`
- 原本PDF：`data/recommendations/2026/sources/course-offerings.pdf`
- 出典ページと原表セル：`raw-rows.json`
- 原本・セルのSHA256とページごとの番号照合：`extraction-audit.json`

原表は[2026年度の公式開設一覧](https://www.iess.niigata-u.ac.jp/acpb/upload/20260327161315092692700.pdf)、2026-03-13時点。冊子6〜133ページ／PDF8〜135ページから抽出したGコード1,228開講は、全ページで本文と表セルの番号が一致している。英語・初修外国語・自然系共通専門基礎の代表行は画像でも照合済み。

旧 `liberal-catalog.json`、`sis-year2-candidates.json`、`quality-report.json` は `archive/` に移動して保持し、完全削除しない。生成物・原本・保管版は全てGit対象外。学生CSVを収集・保存には使わない。

シラバスの概要・評価方法は未取得であり、簡易JSONから項目自体を外した。[公開シラバスのrobots.txt](https://syllabus.niigata-u.ac.jp/robots.txt)による自動巡回禁止の確認結果は年度設定に保持する。

## 5. 再生成

初回起動だけなら[手渡しZIP](handoff.md)から実行用JSONを復元でき、PDF解析依存は不要である。ZIPには公開原本・抽出セル・監査結果も含めるため、以下の通常生成もネットワーク取得なしで実行できる。

原本と抽出セルがある現在の環境では、コマンドは1つでよい。有効な抽出セルを自動再利用し、簡易JSONと調査READMEを生成する。

```bash
.venv/bin/python scripts/build_liberal_catalog.py
```

初回だけ、開発専用のPDF依存を入れて公式資料を取得する。

```bash
.venv/bin/python -m pip install -r requirements-catalog.txt
.venv/bin/python scripts/build_liberal_catalog.py --download
```

原本・セルが変わり整合確認に失敗した場合は、`--extract-only` で再抽出してから通常の生成を行う。資料ページ数・見出しが変わった場合は年度設定とアダプターを確認する。別年度は新設定を追加し、既存年度を上書きしない。学年ごとの再生成は不要。

PDFの開発依存、サーバーの実行依存、学生CSVの処理は分離したまま。カタログはサーバー側で読み、Composeではこの公開JSONだけを読み取り専用で配置する。学務規則・配賦・既存の集計APIは変更しない。
