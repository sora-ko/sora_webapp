更新日: 2026-10-27。現行MVPの初回配置は[引き継ぎ手順](handoff.md)にまとめる。既存の監査記録は履歴として保持し、未修正の保守課題を完了扱いにしない。

## 1. 優先順位の考え方

1. 学生データの漏えい防止と、誤判定を出さない仕組みを優先する。
2. 公式資料から確認できる事実を年度別データへ移し、推測が必要な箇所は実装しない。
3. CSV解析、分類、単位の配賦、要件判定、表示を別々にテストできる順で進める。
4. `unknown` を保持したまま部分的な結果を返せるようにしてから、画面へ判定を出す。

## 3. 承認を待たず進められる順序

1. RULE-002の分類表記を公式資料と照合し、確認できない表記を要確認一覧へ追加する。
2. RULE-003の83件の科目名・別名を今後のCSV形式差へ対応させ、公式資料の改訂時もページ単位で照合する。
3. RULE-004の個別必修確認を、別年度・別プログラムの科目一覧でも検証する。
4. 他大学単位認定、留学生代替、早期卒業はMVP対象外として保持し、要望が出た場合に改めて必要な入力と規則を確認する。
5. 新しい年度・プログラム用の架空プロファイルを使い、追加手順の回帰テストを拡充する。

未確認の配賦規則を確定値として実装する作業は、学務上の確認が得られるまで実行しない。履歴書換え前のローカルcloneやキャッシュからCSVを再流入させないよう、共同利用者は更新後の`main`へ同期する。
