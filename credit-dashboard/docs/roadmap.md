# 開発ロードマップ

更新日: 2026-11-04。集計・進級卒業判定・教養候補検索・不足単位の探索までのMVPは実装済み。[引き継ぎ手順](handoff.md)と[機械可読なAPI契約](../contracts/README.md)で同じ環境・型・応答例を共有し、フロントエンドとバックエンドの分業を進める。

## Milestone 1: 安全なCSVアップロードと表示

**状態: 完了（2026-10-22）**

- `POST /api/v1/reports` の追加
- CSVをメモリ上で解析し、原本を保存しない
- ファイルサイズ・形式・必須列の検証
- フロントエンドのファイル選択、送信、進捗、再試行
- 既存の集計・科目一覧をアップロード結果から描画
- 氏名、学籍番号、所属、学年を画面に表示
- 可変数の科目行をファイル終端まで解析
- 合格かつ単位数確定の科目だけを取得単位へ算入
- 個人情報を含まないログ
- API・画面・非保存性のテスト

完了条件は `requirements.md` のリリース1受け入れ条件をすべて満たすこと。

## Milestone 2: 2025年度カリキュラム分類

**状態: MVP範囲は完了。未知の表記への対応は継続保守**

- 教養系の細区分を公式規程に沿って分類
- 専門基礎・専門応用とA〜Eを正規化
- 不明・曖昧な科目を警告
- 科目分類規則のデータ化と出典ページの保持

## Milestone 3: 進級・卒業要件判定

**状態: MVP範囲の第2・第4年次進級・卒業の三値判定と学年別表示を接続済み**

- 第2年次進級条件（完了）
- 第4年次進級条件（専門基礎B余剰を決定的に配賦し、全条件充足時は総合`satisfied`、分類が不確定なら`unknown`）
- 卒業資格条件（教養内訳、専門系必修16科目の個別確認を含め、全条件から総合三値を計算）
- `satisfied` / `not_satisfied` / `unknown` の三値判定（全3要件へ接続済み）
- 不足単位の表示と個別必修の修得・未修得・判定不能の表示
- 判定根拠と公式資料リンクの表示（全3要件へ接続済み）

## Milestone 4: GPA・成績分析

**状態: 将来。教養探索のMVPより後に検討する**

- 得点、評価、GPの入力品質確認
- 公式式による学期GPA・累積GPA
- 科目群、年度、学期ごとの傾向
- 再履修・取消・認定科目の扱いを確定

## Milestone 5: 履修候補探索

**状態: 教養に限定したMVPは完了（2026-10-27）**

- 成績と独立した曜限候補API、成績CSV・履修表CSVを照合する不足単位の探索API
- 2026年度の公開開設一覧から309開講を収録。旧代表63開講と同じ抽出条件で、100枠中85枠を保持し、学年では絞り込まない
- 卒業の教養条件を1科目ずつ仮評価し、同名修得済み・登録済み・全曜限の重複を除外
- 教養が充足していれば、専門・共通超過分・総計の不足だけでは教養を推薦しない
- 要確認の候補、履修許可未確認、独立した候補であることを表示
- 専門83科目のマスターは分類・個別必修用。専門の推薦、順位付け、先修条件、複数候補の組合せは対象外

## 次の段階: 分業と保守

2026-11-04に、作成から固定20分の短期セッション基盤と、解析結果のメモリ保持・復元（SESSION-002）を実装した。操作・再取得では延長しない。両画面の再読込、復元結果による不足探索、期限・削除・競合・非永続化を検証した。2026-11-11の指定によりSQLite・共有評価・評価による順位付けは保留とし、現在はセッションの検証・文書・引き継ぎを仕上げる。[段階別の計画](session-and-ratings-plan.md)と[セッションAPI](session-api.md)を参照する。

1. Gitに含まれるコード・公開カタログ・架空CSVだけで、初回起動・テストを再現する。ZIPの展開は不要。
2. 成績・履修表・2種類の候補APIの契約を共有し、参考UIを置き換える。変更する契約は同時に文書・テストへ反映する。
3. 整備済みの応答スキーマ・型・架空例を契約テストで維持し、参考UI内部の依存、規則セレクターの検証、未使用コードの整理を保守タスクとして進める。
4. 新しい規則へ展開する前に、[規則データの制約](rule-data.md#8-現行スキーマ評価器の拡張上の制約)と[バックログ](backlog.md)を確認する。
