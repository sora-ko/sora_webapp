# 教養科目の履修推薦：設計メモ

2026-10-26からの利用者指定の要件と、2026-11-11時点の実装を記録する。履修表の読み取り、タブ切替の参考UI、Gコードカタログ生成、指定枠の候補検索、修得単位と空き時間を照合する教養探索をAPI・画面から利用できる。順位付けと複数候補の履修計画は未実装である。

## 1. 確定した範囲

- 最初の対象は新潟大学工学部・知能情報システムプログラム・2025年度入学の既存MVPとする。
- 推薦は教養科目だけ。専門科目を教養へ回す既存の集計方針と、推薦候補の対象範囲は別に扱う。
- 不足単位の探索では教養の必修・選択必修・選択・合計がすべて充足したら推薦を止める。専門と共用する超過分や総計の不足だけでは教養を推薦しない。未充足の教養条件を改善する候補だけを選ぶ。
- 2026-10-27の利用者指定により、学生の学年は候補検索に使わない。任意のターム・曜日・時限にある教養科目の表示と、不足単位を補う効果の探索は別APIとする。単位集計の学年別表示とは分離する。
- 開講期間・曜日・時限が明確な通常授業だけを候補とし、集中講義・未定・空欄・解釈不能を除外する。
- 取り込んだ曜限は変更されない前提。対象年度・タームの選択は必要で、過年度の開講情報を現在のものとして流用しない。
- 2026-10-28の利用者指定により、個人情報を含まない実行用カタログと調査READMEはGit管理する。原本・抽出キャッシュ・旧版・手渡しZIPはGit対象外を維持する。
- 履修表の開講番号は先頭2桁を20YY年度、次の1桁をタームとして扱う。0の科目は利用者指定のMVP方針で占有時間から除外する。ただし、公式資料には0でも通常の曜限を持つ例があるため、集中講義の公式判定と同一視しない。

## 2. 画面分離と短期セッション

単位集計・時間割・推薦を別の機能として扱い、フロントエンドのページ構成やフレームワークは担当者が決める。参考UIはタブ切替を維持し、通常画面・試作画面の双方で短期セッションからの復元に対応する。

```text
ブラウザー（表示・一時的な状態）
  ├─ 成績・時間割・推薦の画面
  └─ static/session-client.js（DOM非依存）
          │ Cookieと専用ヘッダー、初回のみCSV
          ▼
バックエンド
  ├─ CSV解析・分類・学務判定・時間重複確認
  ├─ 解析済みJSONをメモリ保持（作成から固定20分）
  └─ 復元・個別クリア・保持結果を使う推薦API
```

元Fileはブラウザーのメモリだけに置く。サーバーでは元CSV・ファイル名を保持せず、検証して生成した成績・履修表JSONだけを保持する。ページの再読み込み・HTML遷移ではJS変数が初期化されるため、起動時にGET workspaceで復元する。ファイル選択欄は復元せず、再解析するときにだけ選び直す。

LocalStorage・SessionStorage・IndexedDB・Cache Storage・URL・履歴stateへ学生データを置かない。作成から20分で操作にかかわらず失効し、クリア・終了・再起動でも復元できなくなる。同じブラウザープロファイル内のタブではCookieを共有する。期限切れや終了は表示とローカル参照も破棄する。

元File、公開プロファイル、解析済みかどうかを`static/workspace-state.js`で共有する参考実装は、独自フロントの状態管理へ置き換えてよい。通信・期限・更新番号はDOM非依存のクライアントへ分離する。詳しいAPI・手順は[セッションAPI](session-api.md)を参照する。

## 3. フロントエンドとバックエンドの境界

フロントエンドは入力選択、画面切り替え、通信、状態管理、表示を担当する。分類、単位配賦、不足、曜限の重複判定はバックエンドが返す。ブラウザーから渡された解析JSONを正本として受け入れるAPIは設けない。

既存の`POST /api/v1/reports`・`timetables`・`recommendations`・`recommendation-searches`はCookieなしで使える契約を保ち、各要求の元CSVを検証する。これらへCookieを付けただけでは結果を保持しない。CSVなしのカタログ閲覧も利用できる。

追加のsession配下では成績・履修表を一度CSVから解析し、保持結果を`GET /api/v1/session/workspace`で返す。以後の候補閲覧・不足探索は年度・曜限等の条件だけを受け取り、サーバーが保持する結果を利用する。両方式は同じ既存判定器・探索関数を使い、学務規則を変更しない。

新しい成績CSV・規則プロファイル・履修表・対象タームへ変更した場合は古い推薦を無効にする。CSRFと更新番号を照合し、別操作・削除・期限切れ後に完了した処理で結果を復活させない。未知の不足は要確認へ分け、未確定の履修中科目を取得単位へ加えない。

修得済みは番号または明示的に正規化した科目名で推薦から除外する。教養条件がすべて充足なら不足推薦を止める。各候補を1科目ずつ仮追加して再評価し、合計・分類別の改善量を合算しない。複数候補の組合せ最適化は未実装。SQLite・共有評価・評価による順位付けは2026-11-11の指定により保留中。

## 4. 開講データと学生データの分離

| 種類 | 保存・Git管理 |
| --- | --- |
| 学生の成績・履修表CSV | 処理中のメモリのみ。原本・ファイル名を保持・永続保存しない |
| 学生の解析結果 | サーバーメモリで作成から固定20分。ファイル・DB・ブラウザー永続ストレージ・Gitへ保存しない |
| 公式資料から取得した推薦用カタログ | 個人情報を含まない実行用JSONと調査READMEだけを許可リストでGit管理 |
| 公式原本・抽出セル・監査結果・旧版・旧手渡しZIP | ローカルに保持しGit対象外。起動には不要 |
| 入学年度別の学務規則・既存科目マスター | 既存の`rules/`配下でバージョン管理を維持 |
| カタログの検証・生成コード、スキーマ、自動テスト | Git管理。確認済みの架空CSV3点もGit管理し、他のCSVは除外 |

公開の開講カタログだけをサーバー内で再利用することは、学生の解析結果をキャッシュすることとは異なる。入学年度の規則と開講年度のカタログを分け、同じ科目に複数の開講枠がある場合も保持する。

Dockerでは`data/`をイメージへ含めず、Composeで公開の`liberal-catalog.json`だけを読み取り専用で配置する。学生CSVの保存先を作ったり、`data/`全体をマウントしたりしない。

## 5. 公式資料の候補

取得方法の調査で確認した入口は次のとおり。2026年度の開設一覧からGコード1,228開講を抽出し、全ページの番号照合と代表行の目視確認を行った。対象者条件の複雑な表記は採用を保留する。成績との照合は既存の名前正規化に対応し、未知の別名や同等科目の推測は行わない。

- [教育基盤機構・授業科目関連](https://www.iess.niigata-u.ac.jp/intramural.html)：年度ごとの授業科目開設一覧、Gコード科目授業時間表。
- [2026年度授業科目開設一覧](https://www.iess.niigata-u.ac.jp/acpb/upload/20260327161315092692700.pdf)：科目区分、開講番号、単位、開講時期、曜限、主聴講対象等。
- [工学部・在学生向け資料](https://www.eng.niigata-u.ac.jp/student/)：専門の推薦には使わないが、履修表に曜日・時限がなく開講番号だけがある場合、登録済み専門授業の占有時間を特定する資料として必要になり得る。

教養だけを推薦する場合も、時間の重複を避けるには登録済み専門授業を含む時間割が必要である。

生成データの場所、契約、G限定の範囲、再生成手順は[教養開講カタログ](liberal-catalog.md)を参照する。利用者の簡素化要望により、2026-11-04以降は全学部向け・学年絞り込みなしの309開講をschema version 3のJSON一つで使う。旧代表63開講への削減も生成オプションで再現できる。旧版は保管し、出典は別管理する。公開シラバスはrobots.txtが自動取得を禁止しているため巡回せず、授業概要・成績評価方法を簡易JSONへ含めない。開講情報の整備と、授業内容の全文取得や履修許可判定を区別する。

## 6. 履修表入力の確認結果と残りの作業

利用者提供CSVを保存せずメモリで確認し、曜日×時限のグリッドから開講番号と占有時間を取得するアダプターを実装した。入力は既存の成績CSVと異なる。個人情報・実際の履修内容をfixtureや文書へ転記せず、架空データだけで再現テストする。

- 曜日は列見出し、時限は行見出しから取得でき、通常授業の時間特定のためだけに専門の開講一覧を別途用意する必要はない。
- 同じ曜日・時限の別ターム科目、同じ科目の複数曜日・時限を保持する。見出しと全体行数を固定しない。
- 0の科目の除外はMVP方針として分離し、除外した授業との重複を未確認とする注意書きを返す。
- 履修取消等をこの形式から区別する規則は確認できていないため、表示された通常科目を占有時間として読み取る。合格・単位修得とは扱わない。
- 開講カタログと成績の照合は、番号または明示的に正規化した科目名の一致に対応した。未知の別名、推薦順位、受講対象者条件の複雑な表記は引き続き未実装・要確認である。

既存の成績CSVには曜日・時限がないため、推薦にはこの履修表も必要である。将来、開講番号しかない別の履修表形式へ対応する場合は、時間割照合用データを別途用意する。

開講番号欠落、通常科目の時間割外配置、年度・タームと学期の不整合を「授業がない時間」として扱わない。未掲載曜日・時限も、確認済みの空き時間と断定しない。
