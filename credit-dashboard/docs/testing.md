# テスト方針

更新日: 2026-10-28。引き継ぎ検証は第21節、教養候補の対象共有は第22節、API契約からの試作UI検証は第23節、ZIP不要の配布確認は第25節。過去の日付・件数は実施当時の記録として保持する。架空CSV3点と実行用の公開カタログはGitに含まれるため、復元作業なしでテストする。

## 1. 原則

- 実在する学生のCSVをリポジトリへ追加しない。
- テストデータは架空の氏名、在籍番号、科目結果で作成する。
- 公式規則の境界値をテスト名と期待値から追跡できるようにする。
- 分類不能な入力に対し、都合のよい分類をしないことをテストする。

## 2. CSV解析テスト

- UTF-8、UTF-8 BOM、CP932
- 前置き学生情報あり・なし
- 必須列不足、重複列、列順変更、余分な列
- 空ファイル、空行、改行コード差
- 引用符、カンマを含む科目名
- 整数・小数・空・負数・非数の単位
- 合、否、空欄、未知の合否
- No.重複、科目名空欄、科目区分空欄
- 同名科目で開講番号が異なるケース
- 科目行が0件、1件、多数のケース。サンプルの行数へ依存しない
- 見出し以降の空行と、科目ではない非空行
- `合否=合` だが単位数が空欄の科目を取得済みに数えない

## 3. アップロードAPIテスト

- 正常な1ファイル
- ファイルなし、複数ファイル
- 0バイト、上限ちょうど、上限超過
- 偽の拡張子・MIME type
- 解析エラーのHTTPステータスとエラーコード
- レスポンスのschema_version
- 連続する2リクエストのデータが混ざらない
- CSV本文と個人情報がログに出ない
- プロジェクト、一時ディレクトリ、DBへファイルを作らない
- 登録済み`profile_id`の選択と、未登録IDの拒否
- 在学期間の正常値・手入力による上書き・学年からの補完・学年も入力もない場合・負数・非有限値
- プロファイル一覧に学生データが含まれない

## 4. 画面テスト

- ファイル未選択時の操作
- 送信中の多重送信防止
- 成功、警告、エラーの表示
- 再アップロード時に前回結果を適切に破棄
- キーボードだけでの操作
- 画面幅320px程度で主要情報を閲覧可能
- 氏名・在籍番号の表示方針
- 氏名・学籍番号を表示しても、ログとブラウザー永続ストレージには残らない
- APIが不正なJSONを返した場合の安全なエラー

## 5. 学務規則テスト

規則プロファイルのID・出典参照・条件IDの一意性・要確認事項の参照整合性を先に検証する。判定を追加するときは次の境界値を追加する。
別年度・別プログラムを追加するときは、既存プロファイルの期待値を変更せず、選択したプロファイルの分類規則がパーサーへ渡ることもテストする。

### 第2年次進級

- 総計31 / 32 / 33単位
- 指定5科目が3 / 4 / 5単位
- D科目を含めると32だが、除外すると31となるケース
- 在学期間不明は `unknown`

### 第4年次進級

- 総計103 / 104 / 105単位
- 専門66、教養32、共通枠6の各境界
- 専門基礎Bの余剰を専門応用Bへ算入
- E科目6単位までは算入し、7単位目を算入しない
- D科目を算入しない
- 専門応用Bの最低26単位をB・C・Eの追加11単位へ二重計上しない
- 専門基礎Bの超過を専門応用Bへ振り替えた後も二重計上しない
- CSV学年が2・3年なら第4年次進級と卒業だけを表示する
- 夜間主科目は含まれないMVP前提を表示する。夜間主の自動検出は対象外
- 取得年度・学期を使う評価では、第3年次終了後の単位を混入させない

### 卒業

- 総計123 / 124 / 125単位
- 専門82、教養36、共通枠5 / 6 / 7単位の各境界と、両区分の超過を合算するケース
- 教養のCSV「必選区分」を卒業要件区分へ直接読み替えず、科目区分ごとの最低枠へ充当後の残余を選択へ算入する
- 大学学習法、英語、初修外国語、健康・スポーツ、情報リテラシー、人文社会・教育科学、新潟大学個性化科目、自然系共通専門基礎、自然科学の各境界
- 人文社会・教育科学の必修4単位と、人文社会・教育科学または新潟大学個性化科目の選択必修2単位を分離する
- 情報リテラシー（必修指定科目を除く）、自然系共通専門基礎、自然科学から選択必修10単位を配賦する
- 自然科学10、自然系共通専門基礎6＋自然科学4、対象3区分9、対象3区分12から選択必修10＋選択2の境界
- エンジニアのためのデータサイエンス入門を必修2と選択必修10へ二重計上しない
- 「工学リテラシー入門」を部分一致で判定し、分野名や括弧の種類を区別しない。別名称の大学学習法はこの必修2へ算入しない
- 健康スポーツ科学実習ⅠとⅡを区別する
- 英語基礎L/Rを英語でなく人文社会・教育科学として扱う
- 専門基礎B余剰の振替
- 専門応用Bの最低28単位をB・C・D・Eの追加17単位へ二重計上しない
- 区分合計は満たすが個別必修が不足するケース
- 一覧外の専門科目はMVP方針で教養の選択だけへ入り、専門A/Bや教養の必修・選択必修細枠へ入らない
- 夜間主科目なし、留学生代替と早期卒業は対象外というMVP前提を表示する
- 既知の他大学単位ラベルはCSV取得表示を残しつつ、全要件から除外する
- 在学期間不明は `unknown`
- CSV学年が1年でも卒業資格条件の教養内訳を表示する

### 学年別表示

- 1年: 第2年次進級、卒業
- 2・3年: 第4年次進級、卒業
- 4年以上: 卒業
- 学年欠落・未知表記: すべてを表示し、任意入力もなければ在学期間を`unknown`にする

## 6. 回帰テスト

- 公式CSV形式の変更を確認したら、匿名化した最小再現データを追加する。
- バグ修正には、修正前に失敗し修正後に成功するテストを追加する。
- 規則改訂時は既存年度の期待値を変更せず、新しい規則セットとテストを追加する。
- 各conditionとallocationが、資料・冊子頁・PDF頁・表の行列・注記または結合セル範囲へ追跡できることを検証する。
- 配賦済み単位の合計が対象となる一意な確認済み単位を超えないこと、科目順で結果が変わらないこと、有効単位の追加で結果が悪化しないことを検証する。
- 未知のselectorキー、不正な値型、曖昧なprefixまたはaliasを黙って受理しないことを検証する。

## 12. 参考UIのブラウザーテスト

`scripts/check_frontend.cjs`はPlaywrightを提供する開発環境で実行する。アプリの実行依存には追加せず、フロントエンドを置き換えるときも独立した確認に使う。実行先はHTTPのlocalhostだけに制限し、ページからの外部リクエストも遮断する。

```bash
node scripts/check_frontend.cjs
```

Playwrightが通常のモジュール検索パスにない場合は`PLAYWRIGHT_MODULE`にその絶対パスを指定する。Windowsの既存Chromeがある環境ではそれを、その他ではPlaywrightのChromiumを使う。必要なら`CHROMIUM_EXECUTABLE`でブラウザーを指定できる。画像は既定で保存せず、必要時だけ`--screenshot-dir`に保存先を指定する。CSVとAPI応答、トレース、動画は保存しない。

架空CSVをスクリプト内で生成して、実際のアップロード・描画・操作を確認する。

- 初期表示、キーボードでのタブ切替、ファイル未選択エラー
- 実APIの履修表表示、タームごとの占有枠・開講番号の分離、番号0の注意事項
- 集計APIの結果と履修表の独立、タブ切替での保持、各機能のクリア
- 320・768・1440pxのページ幅。横スクロールは時間割・科目表の内部に収める
- 未解決がある場合の「未確認」、科目がない学期の両ターム表示、対象期間不明時に空きを断定しない表示
- ファイル選択・ドラッグ＆ドロップ・不正CSV・不正JSON・API版違い・API未反映の表示
- 送信中のクリア後に古い応答で結果が復活しないこと。中断が効かない状況も模擬する
- 学生情報をHTMLとして実行しないこと、在学期間変更で古い集計を無効化すること

## 13. 公開の教養開講カタログ

`tests/test_offering_catalog.py`と`tests/test_catalog_import.py`は架空の科目・番号・対象とPDFの架空セルだけで確認する。実在する学生CSV、取得したPDF、生成したカタログをfixtureとして読まない。PDF依存は遅延読込とし、通常のテストには開発用PDFパッケージを必須にしない。

- 学期・ターム・通年、全角英数字、正の小数単位、不明・非有限・0単位の保留
- 複数曜日・単一時限、単一曜日・複数時限、明示リストの折返し。複数×複数の曖昧な組合せは推測しない
- 番号0でも明記された期間・曜限は保持し、候補からはMVP方針で除外
- 期間と番号の矛盾、未知分類、集中・指定曜限・オンデマンドを通常の候補にしない
- 主聴講対象の学年・対象外条件と、分野・クラス・再履修等の未解決条件の区別。受講許可を推測しない
- 同名別番号の保持、同一番号の衝突拒否、別学部・学年の対象へ差し替え可能な境界
- 出典と未取得の概要を保持し、不明な情報を作らない
- PDF本文とセルの独立した番号照合、欠落した番号、見出し変更、原本ページ数変更を検出する

実資料の生成監査はテストfixtureとは別に行い、結果をGit対象外の`extraction-audit.json`へ残す。旧版の`quality-report.json`は簡易化に伴い`archive/`へ保持する。2026年度はGコード1,228件の照合が全ページで一致し、原表の画像でも英語・初修外国語・自然系共通専門基礎の代表行を確認した。収集範囲と残る未取得情報は[教養開講カタログ](liberal-catalog.md)に記載する。

## 15. 時間割のマスからの候補取得（初回の確認記録）

`tests/test_recommendations.py`に30件を追加し、全290件が成功した。カタログも履修表も架空値で、実在学生データや実カタログをfixtureとして読まない。
