# 学務規則データ設計

## 1. 目的

学務規則をPythonコードへ直接埋め込まず、大学、学部、プログラム、入学年度ごとの不変なプロファイルとして保持する。新しい年度は別ディレクトリへ追加し、既存年度を上書きしない。

現在のプロファイルは次に置く。

```text
rules/niigata/engineering/smart-information-systems/2025/profile.json
```

構造の機械検証用に `rules/profile.schema.json`、実行時の意味検証用に `academic_rules.py` を使用する。ランタイム検証は外部パッケージを追加せずPython標準ライブラリだけで動作する。

標準課程表を転記する科目マスター用には`rules/course-catalog.schema.json`と`validate_course_catalog()`を用意している。2026-10-26に、工学科共通・情報電子分野導入・知能情報システム固有の専門科目83件を同ディレクトリの`course-catalog.json`へ転記し、CSV分類へ接続した。各科目に科目群、A〜E、単位数、標準年次、明示的な別名、必修の対象要件、根拠頁を記録する。公式資料で確定しない開講番号は`null`とする。

2025年度知能情報システムプログラムについて、公式資料の参照箇所、表の行・列・結合セル、判断理由、現行との差異は`docs/rule-verification-2025-sis.md`に記録する。一般設計、採用した規則、特定年度の検証記録を一つの文書へ混在させない。

## 2. データの境界

規則プロファイルへ入れてよいもの:

- 対象大学、学部、プログラム、入学年度
- 公式資料のURL、規則名、冊子ページ、PDFページ
- 科目分類コード、最低単位、算入上限、除外、振替規則
- 未確認事項と、その確認状態

入れてはいけないもの:

- 氏名、学籍番号、成績などの学生データ
- 根拠資料にない推測値
- 複数年度を暗黙に共用する値

## 3. 状態

要件ごとの `status` は次の意味を持つ。

- `partial`: 根拠のある一部条件は評価できるが、総合判定に不足入力があり得る。
- `blocked`: 個別必修や認定単位の扱いなど、実装前に確定すべき事項が残る。
- `ready`: 根拠、入力、配賦規則、境界値テストが揃っている。

根拠の `evidence_status` は次の意味を持つ。

- `transcribed`: 公式資料から転記したが、別担当者による照合はまだである。
- `verified`: 公式資料とページ単位で再照合済みである。
- `needs_confirmation`: 資料だけでは表記や解釈を確定できない。

`blocked`または`needs_confirmation`を、都合よく`ready`や確定値として読み替えてはならない。

## 4. 規則プロファイルの主要要素

- `scope`: 対象大学、学部、プログラム、入学年度
- `source_documents`: 正本となる公式資料
- `classification`: CSV表記から正規化区分への対応
- `classification.course_catalog_path`: `rules/`配下の科目マスターへの相対パス。パスの逸脱と異なる`profile_id`のマスター利用を拒否する。
- `classification.outside_catalog_policy`: 一覧外専門をどう扱うか。現在は利用者指定の`liberal_elective`を明示する。
- `mvp_policy`: 利用者が指定した対象範囲・前提・公式規則との差と、その決定日。`notes`はAPIと画面にも返す。
- `requirements`: 第2年次、第4年次、卒業等の条件
- `conditions`: 最低単位、在学期間、指定科目群等の個別条件
- `allocation_rules`: 除外、上限、余剰振替、二重計上防止
- `open_questions`: 未解決事項。要件側からIDで参照する

条件は安易な日本語文のまま保存せず、`kind`、`minimum`、`selector`へ分ける。出典は各要件の`source_refs`に冊子ページとPDFページを併記する。

## 5. 現時点の実装範囲

- `classification.py` は2025年度プロファイルの分類表を読み込む。
- `classification.py` と `parser.py` はAPIで選択されたプロファイルを受け取り、対象固有の区分表を使う。
- `requirement_evaluator.py` は第2・第4年次進級および卒業の単位・在学期間・個別必修条件を評価する。
- 在学期間は任意入力を優先し、未入力なら「留年・編入なし」のMVP前提でCSVの学年を使用する。どちらも得られなければ、その条件と総合結果を`unknown`にする。
- 閾値未達でも未確定科目が影響し得る場合は`not_satisfied`ではなく`unknown`にする。
- 第4年次進級と卒業は、専門・教養の最低単位超過分を共通6単位へ合算する。専門基礎Bの10単位超過分は専門応用Bへ決定的に振り替える。卒業の個別必修を含む全条件充足時に総合`satisfied`とし、確定した不足があれば`not_satisfied`、それ以外で分類不能科目が結果へ影響するときは`unknown`にする。
- 教養系のCSV「必選区分」は卒業要件表の3区分へ直接対応させず、科目区分・指定科目名で必修枠、選択必修枠の順に充当し、最後に残余を選択枠へ数える。人文社会・教育科学の必修4単位を先に確保し、その残余と新潟大学個性化科目を選択必修2単位へ充当する。別の選択必修10単位は情報リテラシー（必修指定科目を除く）・自然系共通専門基礎・自然科学の共通枠として集計する。
- 科目マスターは分類へ接続済み。CSV上の既知専門系科目へ名前照合し、一致した群・A〜Eを採用する。一覧外はMVP方針により教養の選択へ分類し、原科目区分と分類理由を保持する。教養・未知区分を一覧照合で強制的に専門へ上書きしない。
- 科目マスターの単位数でCSV単位数を上書きしない。`required_courses`条件を評価するときは、当該要件IDを`required_for`に持つ必修項目ごとに修得を確認し、科目別の三値と理由を返す。
- `course_name_contains_any`で工学リテラシー入門の部分一致を表現する。分野名を区別しない方針はプロファイル内の文字列で制御し、評価器に科目名を埋め込まない。
- 専門応用のB/C/D/E残余枠は、専門基礎Bと専門応用Bの最低枠へ配賦した後の単位だけを数える。
- APIと画面は条件別説明、不足値、根拠ページ、未解決事項を表示する。
- `GET /api/v1/rule-profiles`は登録済みプロファイルと、各プロファイルで実装済みの判定IDを返す。

## 6. 年度・プログラム追加手順

1. 対象年度の公式資料URL、版、適用対象、確認日を固定する。
2. 大学規則、学部規程、細則、最低単位表、プログラム科目表、標準課程表、履修上の注意を列挙する。
3. 表ごとに冊子頁とPDF頁、行、列、備考、結合セルの開始・終了を確認し、専用の検証記録を作る。
4. 大学共通、学部共通、分野共通、プログラム固有、入学年度固有の規則を分離する。
5. 既存ファイルを上書きせず、新しいパスに`profile.json`を作成する。
6. `profile_id`を全プロファイルで一意にする。
7. 最低枠、合計枠、上限、除外、振替、配賦優先順位、二重計上禁止をそれぞれ根拠へ結び付ける。
8. 個別必修、同等科目、名称変更、再履修、他プログラム読替えを科目マスターへ記録する。
9. 編入、再入学、留学生、早期卒業等を通常学生の規則へ暗黙に混ぜず、適用条件または別プロファイルにする。
10. CSVだけで確定できない事項は`open_questions`へ入れ、影響する要件から参照する。
11. `discover_rule_profiles()`で全プロファイルを検証する。
12. 境界値、余剰振替、二重計上防止、例外、既存年度を含む全テストを実行する。
13. 別担当者が公式資料と独立照合してから`verified`へ変更する。
14. 対象年度・プログラムを画面とAPIで明示する。

## 7. 判定を`ready`にする条件

- 数値と算入規則を公式資料の該当ページへ追跡できる。
- 分類不能な科目を含む場合の`unknown`伝播が定義されている。
- 専門基礎Bの余剰振替と共通枠の計算方法が確定している。
- 同じ単位を複数枠へ二重計上しないテストがある。
- 最低値の直前・同値・直後をテストしている。
- 必修科目の個別修得確認を区分合計から分離している。

## 8. 現行スキーマ・評価器の拡張上の制約

2026-10-27時点でも次の制約は残る。教養探索は既存評価器を再利用しており、この節の汎用化を完了したものではない。保守タスクは[バックログ](backlog.md)、別担当の初回配置は[引き継ぎ手順](handoff.md)を参照する。

次は規則プロファイルを追加するだけでは解決せず、エンジン側の変更が必要になる。

- 要件IDと学年別表示が第2年次進級、第4年次進級、卒業へ固定されている。
- 教養／専門、専門基礎／専門応用、A〜EがPythonとschemaの固定列挙である。
- `allocation_rules`は評価器が実行せず、condition側のselector、cap、subtract指定が実際の結果を決める。
- 残余単位は科目ごとの排他的割当てではなく、確認済み合計から先行条件の最低充当値を引いて計算する。単純な包含関係以外には一般化できない。
- 科目マスターはCSV分類・個別必修確認へ接続済み。同等科目の読替え、all-ofとone-ofが混在する選択的な必修条件は未対応。
- selectorの未知キーや値型を十分に拒否せず、誤記が無視される可能性がある。
- prefix分類は複数一致の曖昧性を検出しない。
- 取得年度・学期、入学区分、留学生区分等をconditionの適用条件にできない。
- 教養の共通規則が第4年次進級と卒業へ複製され、修正漏れが起こり得る。

別分野対応を本格化するときは、規則データを`scope`、`sources/decisions`、`taxonomy`、`category_mappings`、`course_catalog`、`credit_pools`、`allocations`、`requirements/applicability`へ分離する。科目単位を一度だけ配賦し、どの科目がどの枠へ使われたかを結果として返す方式へ移行する。

## 9. 根拠記録の最低項目

新しいconditionまたはallocationを追加するときは、少なくとも次を検証記録へ残す。

- 規則IDまたはcondition ID
- 公式資料IDと版
- 冊子頁とPDF頁
- 条文、表題、行見出し、列見出し
- 備考、脚注、結合セルの対象範囲
- 読み取った規則と、採用しなかった別解釈
- 配賦順序、上限、除外、余剰の行先
- 実装selectorまたは科目マスターとの対応
- 一致、不一致、入力不足による`unknown`の別
- 境界値と二重計上防止のテスト名

## 10. 個別必修条件のデータ定義

`kind="required_courses"`は、科目マスターの`required_for`に現在の要件IDが含まれる全科目を確認する。最低科目数や名前をPython側へ固定せず、科目名・別名・正の必要単位数はマスターから取得する。

このkindでは数値の`minimum`を定義せず、`selector`で算入可能な科目を限定する。科目マスターの指定がないプロファイル、対象必修のない一覧、必要単位が空欄・0の必修定義はエラーにする。科目別の確認値は単位配賦から独立させ、総計や残余枠へ再加算しない。
