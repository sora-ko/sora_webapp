# 履修表CSVの読み取り仕様

2026-10-26から知能情報システム向け教養推薦の入力として、`timetable_parser.py`と`POST /api/v1/timetables`、参考UIを実装した。[候補API](recommendation-api.md)で時間割のマスを検索し、別の[単位照合API](recommendation-search-api.md)で成績CSVと空き時間から不足を補える教養を探索できる。順位付けは未実装である。

## 1. 入力形式と取扱い

- 対象は履修照会の時間割形式。成績CSVの19列形式とは別のアダプターで処理する。
- CP932、UTF-8、UTF-8 BOM、CRLF・LFに対応する。
- 前置きの後に曜日の見出しがあり、横軸を曜日、縦軸を時限とする。見出し・時限を探すため、前置きの行数・全体行数・各時限の科目数を固定しない。
- 確認した形式は先頭列が時限、続く列が曜日。曜日列の順番は固定しない。
- 各時限内では、開講番号の行と付随情報2行からなる3行単位で科目が並ぶ。同じ時限・曜日に別タームの科目が複数並ぶ場合も別々に読む。
- 空欄と、この形式で確認した`未登録`を空枠表現とする。ただし付随情報が残っていれば未解決にし、空枠と断定しない。未知の文字列を空枠へ推測で変換しない。
- 氏名・在籍番号・所属・学年・更新日時・件数は返却しない。科目名や教員名の付随情報も保存・返却しない。
- `[年度・学期]`だけは対象コンテキストの整合確認に使用する。不明値は`null`とし、科目からCSV全体の対象期間を勝手に補完しない。
- 読み取りは受け取ったバイト列のメモリ処理だけ。実在CSVをfixture、ログ、ファイル、DBへ転記しない。

## 2. 開講番号の扱い

利用者が2026-10-26に指定した入力規則として、8文字の開講番号の先頭2桁を20YY年度、次の1桁をターム値として扱う。例は架空の番号である。

| 架空の開講番号 | 年度 | ターム・扱い |
| --- | ---: | --- |
| `263G9991` | 2026 | 第3ターム |
| `264G9992` | 2026 | 第4ターム |
| `260G9999` | 2026 | 利用者指定のMVP方針で時間割から除外 |

初版の対象年度は20YY形式であり、世紀をまたぐ推定や、第三桁が5〜9の場合の推測はしない。全角英数字は照合前にNFKCで正規化する。

### 0の扱いに関する公式資料との区別

「第三桁0を一律に集中講義とする」は、公式規則として確定していない。[2026年度工学部時間割](https://www.eng.niigata-u.ac.jp/student/files/timetable_2026_all.pdf)の冊子77ページ（PDF77ページ目）には、`260T4017`研究室体験実習が第3・4タームの金曜4限として掲載されている。したがって、0でも通常の曜限を持つ例がある。

実装は利用者の明示的な除外指定に従うが、属性名を`is_intensive`とはせず、`excluded_by_term_zero_policy`・`excluded_term_zero_course_count`として公式の授業形態との混同を避ける。除外が発生した応答には`policy_notes`を返す。その科目との時間重複は確認していないため、この前提で推薦する際は注意書きを表示する。

この除外は履修表の占有時間に対する方針であり、成績CSVの取得単位や進級・卒業判定から同じ科目を除外する変更ではない。

## 3. 読み取り結果の契約

`schema_version: 1`は履修表リソースの版である。成績レポートの`schema_version: 2`とは別の形式として扱う。

| 項目 | 内容 |
| --- | --- |
| `format` | `niigata-rsrefer-grid` |
| `context` | `academic_year`、`semester`、`term`。読み取れなければ各値は`null` |
| `display_contexts` | 画面で選択できる`academic_year`・`term`の組。通常科目から確認できる期間と、前置きで明示された対象タームを重複なく昇順で返す。第1学期は1・2、第2学期は3・4を含み、科目がないタームも表示できる。年度や期間が不明なら補完しない |
| `represented_weekdays` | CSVで確認できる曜日。月=1〜日=7。未掲載曜日まで確認済みの空き時間とはしない |
| `represented_periods` | CSVで確認できる時限。未掲載の時限まで空き時間とはしない |
| `courses` | 通常タームの`course_code`・`academic_year`・`term`・`slots`。同じ開講番号の複数曜日・複数時限を保持 |
| `busy_slots` | 年度・ターム・曜日・時限を持つ占有枠。重複を除いたもの |
| `excluded_term_zero_course_count` | 0のMVP方針で除外した開講番号の種類数。授業形態が集中と確認された科目数ではない |
| `unresolved_courses` | 番号欠落、通常科目の時間割外配置等。未解決を空き時間とみなさない |
| `ready_for_recommendation` | 当該MVP方針の下で、解析上の未解決・コンテキスト矛盾がないか。カタログ完成や履修許可を示す値ではない |
| `warnings` | `code`、`row_number`、日本語`message`。CSV本文や科目名・学生情報をメッセージへ埋め込まない |
| `policy_notes` | 0を除外した場合の注意事項 |

`row_number`はCSVレコードの1始まりの番号。前置きや引用内改行があるため、一般的な物理行番号と一致するとは限らない。

通常科目の番号から得られる年度・タームが前置きの年度・学期と矛盾すれば、上書き・自動修正せず警告し、`ready_for_recommendation=false`にする。通常科目が時間割外にあれば、直前の時限へ割り当てず未解決にする。

## 4. API

`POST /api/v1/timetables`

- `multipart/form-data`の`file`として履修表CSVを1つ送る。
- 最大5 MiB。拡張子・申告MIMEではなく中身を検証する。
- 現時点では規則プロファイル・学年・対象タームを入力するAPIではなく、履修表の読み取りだけを行う。
- 成功はHTTP 200。警告・未解決があってもJSONを返すので、クライアントはフラグと注意書きを確認する。
- ファイル不足400、不正CSV・見出し不足・値の不正422、文字コード未対応415、上限超過413。形式は既存APIと同じ`error.code`・`error.message`・必要に応じた`error.details`。
- サーバーセッション・レポートID・Cookieによる解析結果の保存はない。応答は`Cache-Control: no-store`。

フロントエンドはこの応答を集計結果とは別のメモリ上の状態として保持する。集計APIの入力・応答契約は変更していない。Docker利用時に追加APIと画面を使うには、更新したイメージへ再ビルドする必要がある。

## 5. フロントエンド担当向けの参考UI

`static/index.html`内で「単位集計」「時間割と教養候補」を切り替える。`static/navigation.js`はタブ操作、`static/app.js`は成績APIと集計表示、`static/timetable.js`は履修表APIへの送信・応答検証・表示を担当する。フレームワークや本番デザインを指定するものではなく、API接続を確認するための参考実装である。

- CSVを選択またはドロップし「履修表を解析」を押す。年度・ターム選択は`display_contexts`を使い、学期からの変換を画面で再実装しない。
- 時間割、通常科目数、選択中の占有枠数、番号0による除外数、未解決数、注意事項、開講番号と曜限の一覧、折りたたみのJSONを表示する。
- 表示する曜日・時限はAPIが返した範囲だけ。確認できた占有枠は「通常授業あり」、未解決がない場合の残りは「通常授業なし」とし、履修可能という判定には使わない。対象期間が選べない、または解析結果に未解決・不整合がある場合、残りを「未確認」とする。
- 0による除外の注意事項をJSON内だけでなく画面にも表示する。科目名・教員名はAPIが返さないため、この画面でも表示しない。
- 集計と履修表の`File`・解析結果は独立したメモリ状態とする。タブ切替時は保持し、各機能の「クリア」と再読み込みで破棄する。サーバーセッション、Cookie、ブラウザーの永続ストレージは追加しない。
- 新しいファイル選択時には当該機能の前回結果を破棄する。送信中の変更・クリアでは中断と世代番号の確認で古い応答を無視する。集計側は規則プロファイル・在学期間の変更時も無効化する。
- マスのクリックで候補APIを呼び、元の履修表Fileをメモリから再送する。候補の全曜限の重複確認はバックエンドで行い、画面では再実装しない。不足単位によるランキングや履修許可は未判定と表示する。
