# プロダクト要件定義

## 1. 文書の位置付け

本書は、成績CSVを解析し、単位取得状況を学生本人に表示するアプリケーションの要求を定義する。
2026-10-27時点では「CSVアップロード、サーバー側解析、ブラウザー表示」に加え、進級・卒業の参考判定、教養の曜限候補検索、修得単位と空き時間を照合する探索までをMVPに含む。

要件の状態は次の語で表す。

- **確定**: 利用者の回答または公式資料で確認済み
- **暫定**: MVPを前進させるための初期値。実装前後に変更可能
- **将来**: 初回リリースの対象外
- **要確認**: 根拠または利用者の判断が不足している

## 2. 対象

| 項目 | 内容 | 状態 |
| --- | --- | --- |
| 大学 | 新潟大学 | 確定 |
| 学部 | 工学部 | 確定 |
| 学位プログラム | 知能情報システムプログラム | 確定 |
| 入学年度 | 2025年度（令和7年度） | 確定 |
| MVPの基準学年 | 現在2年次。同じ2025年度規則で1〜4年次の表示に対応 | 確定 |
| 主利用者 | 学生本人 | 確定 |
| 初期運用 | 個人PCのlocalhost | 確定 |
| 将来運用 | サーバーへの配置を妨げない構成 | 確定 |

MVPの基準対象は、2025年度入学で現在2年次の知能情報システムプログラム所属学生である。同じ入学年度の1〜4年次について、CSVの学年で表示する進級・卒業条件を切り替える。
別の入学年度・学部・プログラムには対応する規則をまだ登録しておらず、正しい判定を保証しない。
対象外であることを検出できる場合は警告し、検出できない場合も画面に対象カリキュラムを常時表示する。
入学年度・プログラムは別の規則プロファイルとして追加し、既存年度の規則を上書きしない。学年は規則を識別するキーではなく、表示・在学期間の評価コンテキストとする。

2026-10-26の決定により、将来も対象大学は新潟大学に限定する。工学部内の別年度・別プログラムへの展開を優先し、設計は他学部へ再利用できるようにする。留学生向け代替規則と早期卒業は対象外、夜間主科目は入力に含まれない前提とする。

## 3. 解決する課題

学生が大学システムから取得した成績CSVを自分で読み解き、取得単位を手作業で分類・集計する負担を減らす。
初回リリースでは、アップロードしたCSVの解析結果を速やかに確認できることを価値とする。

本アプリケーションは大学による公式な成績証明、進級判定または卒業判定を代替しない。
判定結果を追加する際は「参考情報」であることと根拠資料を画面に表示する。

## 4. リリース1の機能要件

### FR-001 CSVの選択

- 利用者はファイル選択UIから1つのCSVを選択できる。
- 通常の入力は、大学が出力したCSVを学生本人が編集せずに利用する前提とする。内容・サイズ・文字コードの検証は維持する。
- ドラッグ&ドロップは暫定要件とする。
- 選択前に、対象が2025年度入学の知能情報システムプログラムであることを表示する。
- ブラウザーはCSVの内容を外部サービスへ送信しない。

### FR-002 CSVの送信

- ブラウザーは選択したCSVを本アプリケーションのバックエンドへ送信する。
- 送信先は同一オリジンを既定とする。
- ファイル名、拡張子、ブラウザーが申告したMIME typeだけを信用せず、内容を検証する。
- 最大ファイルサイズは5 MiBとする。

### FR-003 サーバー側解析

- バックエンドはアップロードされたバイト列をメモリ上で解析する。
- UTF-8（BOM付き含む）およびCP932を受け付ける。
- 必須列を検証し、行番号を含む理解可能なエラーを返す。
- 科目行数を固定せず、見出し以降をファイル終端まで解析する。
- 空行は無視し、科目行と判断できない非空行は黙って捨てず警告または形式エラーにする。
- 科目、単位数、合否、科目区分、必選区分、修得年度・学期等を正規化する。
- `合否` が「合」で、かつ有効な単位数が記録されている科目だけを取得済みとして数える。
- 「合」でも単位数が空欄または不正な科目は取得済みに数えず、未確定またはエラーとして扱う。
- 合否空欄または未知の状態は取得済みに含めず、未確定または警告として扱う。
- 開講コードが異なる再履修行は別科目として扱い、同名または同じ科目マスターIDで名寄せしない。同じ開講コードの重複行は二重計上しない。
- 他大学の単位認定はMVP対象外とする。既知ラベルは要件集計から除外するが、未確認のCSV表記を推測しない。

### FR-004 解析結果の表示

- 取得済み単位、未確定単位、科目数を表示する。
- CSVから取得できた氏名、学籍番号、所属、学年を画面に表示する。MVPではマスクしない。
- 教養系科目と学部専門系科目、および元CSVの科目区分別に表示する。
- 科目一覧を表示し、大分類または科目区分で絞り込める。
- データ欠損や未知の値は警告として表示する。
- 別のCSVを選択して再解析できる。
- エラー時に前回のデータと今回のエラーを混同させない。
- 生のJSON表示は開発用機能とし、一般利用画面では必須としない。

### FR-005 対応状況の表示

- 画面に、選択した対象大学・学部・プログラム・入学年度を表示する。
- 実装済みの判定対象と、未対応の進級・卒業判定を区別する。
- 判定機能を追加した後も、公式判定ではない旨と根拠資料へのリンクを表示する。

### FR-006 第2年次進級条件との比較

- 利用者は登録済みの年度・プログラム別規則プロファイルを選択できる。
- MVPでは留年・編入がなく学年と在学年数が一致する前提とし、在学期間の入力がなければCSVの学年を使用する。
- 在学期間は任意入力（0〜100年）で上書きでき、レスポンスには利用者入力か学年前提かを示す値の出所を含める。
- CSVの学年も在学期間入力もない場合、または分類不能・結果未確定の科目が結論へ影響する場合は`unknown`とする。
- 各条件の確認済み値、不足値、判定理由、根拠資料、未確認事項をバックエンドで生成して表示する。
- フロントエンドで単位条件や進級条件を再計算しない。

### FR-007 学年別の要件表示

- CSVの学年が1年なら、第2年次進級条件と卒業資格条件を表示する。
- CSVの学年が2年または3年なら、第4年次進級条件と卒業資格条件を表示する。
- CSVの学年が4年以上なら、卒業資格条件を表示する。
- 学年が欠落または解釈不能なら要件を隠さず、すべて表示したうえで判定不能を明示する。
- 工学部の教養系卒業要件は、大学学習法、英語、初修外国語、健康・スポーツ、情報リテラシー、人文社会・教育科学の必修、人文社会・教育科学または新潟大学個性化科目の選択必修、情報リテラシー（必修指定科目を除く）・自然系共通専門基礎・自然科学からなる選択必修10単位、選択、教養合計に分け、どの学年でも表示する。
- 教養系のCSV「必選区分」は卒業要件の必修・選択必修・選択へ直接読み替えず、公式表の科目区分・指定科目名に基づいて最低枠から順に配賦する。
- 夜間主科目は含まれない前提とし、留学生代替と早期卒業は対象外であることを画面へ示す。
- 第4年次・卒業要件は専門・教養の最低単位超過分を共通6単位として合算する。専門基礎B超過分は専門応用Bへ配賦し、B/C/D/Eの追加枠では最低枠に使用したB単位を二重計上しない。表示した全条件が充足なら総合も`satisfied`とし、確定した不足があれば`not_satisfied`、それ以外で分類不能・未確定科目が結論へ影響する場合は`unknown`とする。

### FR-008 専門科目一覧との照合とMVP独自分類

- 選択したプロファイルの専門科目マスターを読み込み、科目名・明示した別名と比較する。知能情報システムの一覧には工学科共通と情報電子分野の導入科目を含める。
- CSV上の既知専門系科目が一致した場合、科目マスターの専門基礎／専門応用とA〜Eを使用する。原科目名・科目区分・必選区分は保持する。
- 全半角、ローマ数字、空白の差を照合時に吸収し、CSV表示用接尾辞はプロファイル指定分だけ除去する。
- 一覧にない専門科目は、利用者指定のMVP方針として教養の選択枠へ分類する。教養の必修・選択必修細枠には配賦しない。
- 上記方針は公式の他プログラム科目の専門応用C読替えとは異なることを画面に表示し、各科目へ分類理由を返す。
- 既知の教養区分は維持し、未知区分を「他分野の専門」と推測して教養へ変換しない。
- 大学学習法の必修2単位は、教養科目の名前に「工学リテラシー入門」を含むかで確認する。括弧や分野名は区別しない。

### FR-009 卒業の個別必修確認

- 対象プロファイルの科目マスターで`required_for`に`graduation`を含む各科目を、単位合計と独立して確認する。
- 必修科目名・明示別名の照合後、算入対象の専門科目であり、合格かつ必要単位が確定した修得行がある場合だけ修得済みとする。
- 必修科目がCSVに存在しない、不合格だけ、必要単位に届かない場合は未充足とする。合否・単位数・分類が未確定の候補が結果を変え得る場合は`unknown`とする。
- 同名・異コードの履修は全体単位では別科目として扱うが、ある必修科目の修得を複数回確認しても、別の必修科目の代替にしない。
- 科目ごとの確認は修得単位へ再加算せず、既存の単位配賦と二重計上しない。
- 画面に修得確認数、未修得・判定不能の科目と科目別理由を表示し、すべての卒業条件と合わせて総合判定する。

### FR-010 教養科目の履修推薦（曜限候補API・画面に対応、不足枠による順位付けは未実装）

2026-10-26の利用者指定により、次の範囲で追加する。

- 最初の対象は既存MVPと同じ知能情報システムプログラム・2025年度入学の学生とし、別年度・別プログラムへ差し替えられる境界を維持する。
- 推薦対象は教養科目だけとし、専門科目は推薦しない。集計上の「一覧外専門→教養選択」というMVP方針だけを理由に、専門開講科目を推薦候補へ入れない。
- 公式の授業科目開設一覧等から推薦用の開講カタログを作る。実行用JSONは科目名・開講番号・単位・区分・ターム・曜限の6項目とし、対象者情報は生成時に検証し、出典・監査情報は別管理する。
- 開講期間・曜日・時限が明確な科目だけを候補にする。集中講義、期間・曜限の未定・空欄・解釈不能は候補から除外し、空き時間に開催される科目として推測しない。
- 取り込んだ曜日・時限は変更されない前提で扱う。リアルタイム変更検出は初版の対象外だが、開講年度とタームの一致は確認する。
- 履修表の開講番号の先頭2桁を20YY年度、次の1桁をタームとする。0の科目は利用者指定のMVP除外方針として占有時間から除外し、公式の「集中講義」と断定しない。公式資料に通常授業の例もあるため、除外した科目との重複は未確認という注意書きを返す。
- 既存の成績CSVと、現在の履修表CSVから得た時間割を使い、授業時間の重複がなく、教養の不足条件を改善する候補を理由付きで提示する。
- 判定・単位配賦・推薦順位はバックエンドの責務とし、フロントエンドで再実装しない。推薦による仮の修得結果で実際の取得単位を上書きしない。
- 学生の成績CSV・履修表CSV・解析結果は保存しない。公開の開講情報とは保存場所と取扱いを分ける。
- 取得資料・抽出結果・生成JSON等は`data/recommendations/`へ隔離し、作成前から`.gitignore`で除外する。既存の学務規則プロファイル・検証スキーマはこの除外対象に含めない。
- 集計と推薦は別機能として扱う。参考UIはタブ切替と元Fileのメモリ共有で実装済み。[推薦機能の設計メモ](recommendation-design.md)の保存方針とAPI契約を保ち、フロントエンド担当が画面構成を置き換えられる。

履修表CSVの専用アダプター、`POST /api/v1/timetables`、集計と時間割を切り替える参考UIを実装した。2026-10-27の利用者指定により、候補は学生の学年で変更しない。利用用の公開カタログは全学部向け309候補から代表63開講へ絞る。20通りのターム×時限には全て候補があり、曜日別では85/100枠を保持する。時間割のマスから`POST /api/v1/recommendations`を呼び、候補の全曜限を履修表と照合できる。学年欄が不明でも保留しない。CSVなしのカタログ閲覧にも対応し、未確認と明示する。契約と分業方法は[候補API仕様](recommendation-api.md)、データの範囲は[教養開講カタログ](liberal-catalog.md)を参照する。

修得単位との照合は別の`POST /api/v1/recommendation-searches`で実装した。元の成績CSVと履修表CSVを受け取り、全学年で卒業の教養関連単位条件を共通の基準とする。候補を1科目修得した仮定で既存評価器を再実行し、確定した不足が減る教養を空き時間から探索する。利用者の指定により、開講番号が違っても同名の修得済み科目は除外する。CSV内の再履修行の集計方法は変更しない。未知の不足や同名の結果未確定は要確認候補へ分け、改善量は重複する合計と分類の間で合算しない。参考UIは両タブで選択した元Fileをメモリで共有し、変更・クリア・再読み込みで古い結果を破棄する。契約は[単位照合の探索API](recommendation-search-api.md)。順位付け・候補の組合せ最適化・先修条件・履修許可は今後の作業とする。単位集計の学年別要件表示は変更しない。

2026-10-27の追加指定により、推薦の起点は教養だけを要求する必修・選択必修・選択・教養合計とする。すべて充足なら、専門・共通超過分・総計だけが不足していても教養候補を返さない。教養が未充足の場合も、その教養条件を改善する候補に限定し、共通超過分・総計の効果は付随情報として返す。未確定の教養条件を充足扱いにせず、時限指定の候補閲覧APIは充足状況にかかわらず利用できる。

## 5. リリース1の受け入れ条件

1. 利用者が画面から有効なCP932のCSVを選ぶと、ページ遷移せずに解析結果が表示される。
2. UTF-8の同等なCSVでも同じ解析結果になる。
3. 不正な形式、空ファイル、上限超過、必須列不足について、日本語のエラーが表示される。
4. アップロードしたCSVがプロジェクト配下、OSの一時領域、データベースのいずれにも保存されない。
5. アクセスログおよびエラーログに、CSV本文、氏名、在籍番号、成績が記録されない。
6. ページを再読み込みすると、以前アップロードした解析結果をサーバーから復元できない。
7. 既存の解析テストに加え、アップロードAPIと非保存性の自動テストが成功する。
8. localhostではネットワーク接続なしで主要機能が利用できる。
9. CSV内に値があれば、氏名、学籍番号、所属、学年がマスクされず表示される。
10. 科目行数がサンプルより増減しても、固定件数で打ち切らずファイル終端まで解析される。

## 6. 実装状況

リリース1として次を実装済み。

- `POST /api/v1/reports`によるCSVアップロード
- メモリ内ストリーミング処理と5 MiB上限
- ファイル選択・ドラッグ&ドロップ・解析結果表示
- 合格かつ単位数確定の科目だけを取得済みとして集計
- schema version 2
- 固定CSVを読む旧APIの無効化
- アップロード、上限、文字コード、非保存性、個人情報非ログ、可変行数の自動テスト
- 年度別学務規則プロファイルと科目マスター用スキーマ
- 規則プロファイル一覧・選択APIと、プロファイル駆動の分類
- 第2年次進級条件の三値判定、学年に基づく在学期間の暫定補完と任意上書き、条件別説明、根拠リンクのAPI・画面統合
- CSV学年による表示要件の選択
- 第4年次進級・卒業資格の総合三値判定、確認済み内訳表示、共通6単位の超過計算
- 工学部教養系卒業要件の必修・選択必修・選択別集計と、専門系最低枠の残余単位計算
- 専門科目マスター83件による所属プログラムの分類、一覧外専門の教養扱い、MVP方針の表示、自然科学を含む選択必修10単位、工学リテラシー入門の部分一致
- 履修表CSVの読取、年度・ターム別の時間割、独立した教養の曜限候補API
- 代表63開講の簡易カタログと、修得単位・空き時間からの教養探索API
- 教養充足時の探索停止、同名修得済み科目の除外、要確認候補の分離
- 参考UIのタブ切替、CSVのメモリ共有、結果の折りたたみ、CSV未選択時の案内

卒業必修16科目の個別修得確認を評価器と画面へ接続済み。単位合計だけが充足しても必修未修得なら卒業総合判定は未充足とする。

## 7. 個人情報・セキュリティ要件

- CSV原本は保存しない。
- 初回リリースではデータベースを導入しない。保存が必要となる機能ごとに目的、項目、期間、削除方法を再定義する。
- 氏名、在籍番号、所属、成績は機微な利用者データとして扱う。
- 学生本人が個人PCで利用する前提のため、MVPでは氏名と学籍番号をマスクせず画面に表示する。
- MVPでは利用者認証を実装しない。サーバー公開を行う段階で認証の要否と方式を再検討する。
- CSV本文や解析後の科目データを第三者API、解析サービス、AIサービスへ送らない。
- 外部CDN、外部フォント、アクセス解析は初回リリースで使用しない。
- ファイル内容を数式、HTMLまたはプログラムとして実行しない。
- サーバー公開時はHTTPS、アクセス制御、アップロード回数制限、リクエストサイズ制限を追加する。
- 開発用サンプルとテストフィクスチャには、実在する学生の情報を使用しない。

## 8. 非機能要件

| ID | 要件 |
| --- | --- |
| NFR-001 | 一般的な成績CSVをlocalhost上で2秒程度以内に解析・表示する（暫定目標）。 |
| NFR-002 | Pythonのサポート対象バージョンを明記し、再現可能な起動手順を提供する。 |
| NFR-003 | 判定規則とCSV解析を分離し、入学年度やプログラムを追加できる。 |
| NFR-004 | APIレスポンスにスキーマバージョンを持たせる。 |
| NFR-005 | スマートフォン幅でもアップロード、要約、警告を操作・閲覧できる。 |
| NFR-006 | キーボード操作、ラベル、フォーカス表示、エラー通知を提供する。 |
| NFR-007 | 根拠不明な分類や判定を行わず、`unknown` と警告を返せる。 |

## 9. 将来要件

優先候補は次の順とする。各機能は独立して追加できる設計とする。

1. 別入学年度・別プログラムへの規則プロファイルと科目マスターの追加
2. 新しい分類体系・進級節目に対応する評価器と規則検証の拡張
3. 教養カタログの対象範囲・科目名照合の改善
4. 教養候補の順位付けや複数候補の履修計画（現在は1科目ずつの効果を表示）
5. GPAおよび成績分布の分析
6. 履修中・履修予定科目を含むシミュレーション
7. 科目の成績予測

履修推薦と成績予測は、単なる単位充足判定とは異なる。不確実性、利用データ、説明可能性、誤推薦時の影響を別途要件定義してから実装する。

## 10. 要確認事項

- CSVに「認定」「放棄」「履修取消」「再履修」等が現れた場合の実際の表記と正しい扱い。
- 公式資料が改訂された場合の規則更新責任者。
- 別の入学年度、別プログラムへ対応するときの優先順位。
- 新しい規則プロファイルを公開する際の、公式資料転記とレビューの担当者。
