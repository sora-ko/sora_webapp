# 2025年度・知能情報システムプログラム 学務規則検証記録

第1〜12節は2026-10-23時点の公式資料監査記録であり、「現行」はその監査時点を指す。2026-10-26の利用者判断と分類実装時点の状態は第13節、その後の卒業個別必修の実装は第14節に記録する。公式資料の内容と、利用者が選択したMVP独自方針を区別して追跡する。

2026-10-27の引き継ぎ確認でも監査履歴を保持する。現在は個別必修を含めて卒業を三値判定し、教養探索は既存の卒業評価器を再利用する。推薦停止等の製品方針は[探索API](recommendation-search-api.md)へ記録し、公式の単位条件とは区別する。

## 1. この文書の役割

この文書は、新潟大学工学部の2025年度（令和7年度）入学生について、進級・卒業要件をどの公式資料のどこから、どのように読み取ったかを残す監査記録である。

- 対象: 新潟大学工学部・知能情報システムプログラム・2025年度入学の通常入学者
- 正本: [新潟大学工学部「学生必携 2025（令和7）年度入学生用」](https://www.eng.niigata-u.ac.jp/student/files/hikkei_2025.pdf)
- 再照合日: 2026-10-23
- 再照合方法: PDF本文、表の罫線と結合セル、備考、関係条文、標準課程表を目視で突き合わせた。OCRの文字順や数値の近接位置だけでは表を解釈していない。
- データ取扱い: 公開された公式資料と架空の境界例だけを使用し、学生CSV、氏名、学籍番号、成績は使用していない。

`docs/academic-rules.md`は採用した学務規則の要約、`docs/rule-data.md`は規則データの設計、本文書は根拠と判断過程を担当する。実装が本文書の確定規則と異なる場合、差異を解消するまで「確認済みの仕様」と「現在の動作」を同一視しない。

## 3. 表の読み方

### 3.1 結合セル

工学部規程別表第1は、数値の印字位置だけでは対象範囲を判断できない。次のように罫線が閉じる範囲を確認する。

- 選択必修10単位のセルは「情報リテラシー」「自然系共通専門基礎」「自然科学」の3科目区分を連続して覆う。
- 選択必修2単位のセルは「人文社会・教育科学」「新潟大学個性化科目」を覆う。
- 選択11単位のセルは教養系科目の全行を覆う。
- 必修2単位の情報リテラシーと、選択必修10単位の共通枠は列が異なる。同じ科目の単位を両方へ重ねて数えてよいという意味ではない。

したがって、選択必修10単位を「自然系共通専門基礎だけ」と読むことも、「自然科学はすべて選択11単位へ入る」と読むことも誤りである。

### 3.2 最低単位と科目一覧

最低単位表と標準課程表には役割の違いがある。

- 最低単位表: 進級・卒業時に必要な区分別の下限、上限、除外、振替を定める。
- 工学部規程別表第2: 当該プログラムで、どの科目が専門基礎／専門応用および必修／選択必修／選択／特殊選択に属するかを定める。
- 標準課程表: A–E、単位数、標準履修年次、開講時期、個別必修科目を照合する。

区分合計だけを実装し、科目一覧を確認しないと、他プログラム科目や名称変更科目を誤って所属プログラムのA/B科目として数える可能性がある。

## 4. 教養系の確定規則

### 4.1 必修13単位

根拠は工学部規程別表第1（冊子7頁／PDF11頁）の必修列と備考である。

| 条件ID | 枠 | 単位 | 根拠の読み方 | 現行実装 |
| --- | --- | ---: | --- | --- |
| `liberal_university_study` | 大学学習法 | 2 | 必修列2。履修上の注意では、所属分野で開講する「工学リテラシー入門」を履修する。 | **過大算入のおそれ**。現在は大学学習法区分の全科目を対象とし、所属分野・指定科目を確認しない。 |
| `liberal_english` | 英語 | 2 | 必修列2。履修案内では原則「アカデミック英語入門L/R」。 | 区分合計2として集計。指定科目を科目マスターで確認していない。 |
| `liberal_initial_language` | 初修外国語 | 2 | 必修列2。英語以外の外国語。履修案内ではグローバル理解1単位科目を2単位分履修。 | 区分合計2として集計。 |
| `liberal_health_sports` | 健康・スポーツ | 1 | 備考により必修算入は「健康スポーツ科学実習Ⅰ」に限る。 | 一致。科目名で限定している。 |
| `liberal_information_literacy` | 情報リテラシー | 2 | 備考により必修算入は「エンジニアのためのデータサイエンス入門」に限る。 | 一致。科目名の別名を正規化して限定している。 |
| `liberal_humanities_social_required` | 人文社会・教育科学 | 4 | 必修列4。 | 一致。 |

補足:

- 「英語基礎L」「英語基礎R」は名称に英語を含むが、履修上の注意（冊子64–65頁／PDF68–69頁）では「人文社会・教育科学」として進級・卒業要件へ積算する。科目名だけで英語区分へ再分類してはならない。
- 「健康スポーツ科学実習Ⅱ」は必修1単位へは使えない。選択11単位の全教養残余へ入るかは、正規の科目区分と有効な単位認定を確認して扱う。
- 「データサイエンス総論Ⅰ」は内容重複のため工学部生は履修できないと記載される。異常なCSVに現れた場合の単位取消しまで公式資料は述べていないため、アプリ独自に不合格扱いせず要確認とする。

### 4.2 選択必修12単位

選択必修は独立した2枠の合計である。

#### 情報リテラシー／自然系共通専門基礎／自然科学から10単位

対象となる科目区分は次の3つである。

1. 情報リテラシー
2. 自然系共通専門基礎
3. 自然科学

必修へ充当した「エンジニアのためのデータサイエンス入門」2単位は、選択必修10単位へ再使用しない。正しい例は次のとおりである。

- 自然系共通専門基礎6 + 自然科学4 = 選択必修10
- 自然科学10 = 選択必修10
- 必修指定以外の情報リテラシー2 + 自然科学8 = 選択必修10
- 自然科学12 = 選択必修10 + 選択残余2
- データサイエンス入門2 + 自然科学8 = 必修2 + 選択必修8であり、選択必修10を満たさない

現行`liberal_natural_foundation`は「自然系共通専門基礎」とCSV固有の複合表記だけを対象にしており、「自然科学」と公式の単独「情報リテラシー」を漏らす。このため現行集計は公式規則と不一致である。

#### 人文社会・教育科学／新潟大学個性化科目から2単位

人文社会・教育科学4単位を必修へ先に充当する。その残余と新潟大学個性化科目の合計から2単位を選択必修へ充当する。現行の残余計算はこの順序と一致する。

### 4.3 選択11単位と第4年次進級時の7単位

別表第1の選択11単位セルは教養系の全科目区分を覆う。したがって、必修13単位と選択必修12単位へ**実際に充当した単位**を全教養系の確認済み単位から差し引き、その残余を選択へ充当する。

- 卒業: 選択11、教養合計36
- 第4年次進級: 同じ内訳の選択部分を7とし、教養合計32

最低枠を超えた英語、初修外国語、人文社会、自然科学等も、正規の教養系科目であり他の枠へ未使用なら選択残余になり得る。現在の「全教養から先行枠への実充当分を引く」方式は、この規則には一致する。

### 4.4 公式の教養系科目区分

授業科目区分表（冊子62頁／PDF66頁）は次を定める。CSV固有の表示名と、この正規区分を分けて管理する。

| --- | --- |
| 英語 | 英語、実践英語 |
| 初修外国語 | グローバル理解、ドイツ語、フランス語、ロシア語、中国語、朝鮮語、スペイン語、イタリア語、外国語スペシャル、その他 |

| 人文社会・教育科学 | 人文科学、教育人間科学、法学、経済学 |

## 5. 専門系の確定規則

### 5.1 A–Eの意味

根拠は工学部規程細則第2条（冊子23頁／PDF27頁）である。

| コード | 規則上の種類 |
| --- | --- |
| A | 必修科目 |
| B | 選択必修科目 |
| C | 選択科目 |
| D | 特殊選択科目 |
| E | 自由科目 |

CSVの「必選区分」だけでは専門基礎／専門応用を決められない。科目区分と組み合わせて、専門基礎B、専門応用A等へ正規化する現在の基本方針は正しい。

### 5.2 知能情報システムプログラムの正規構成

工学部規程別表第2（冊子12頁／PDF16頁）および標準課程表（冊子38–40頁／PDF42–44頁）から次を確認した。

- 専門基礎科目群: B科目のみで、標準課程表上は合計18単位
- 専門応用科目群: A科目27単位、B科目40単位、C科目60単位
- D科目: リメディアル演習、インターンシップ、施設見学、特別講義、海外英語研修、国際研修
- E科目: 工学科共通の単位互換協定に基づき修得した他大学開設科目、特設講義等。単位数が別に定められるものを含む。

卒業の専門応用A最低27単位は、標準課程表のA科目総数27と一致する。正規の科目マスターと他プログラム科目のC読替えを適用した後なら、A合計27は全A科目修得と数値上同値になる。しかし現行評価器は科目マスターを参照しないため、Aと表示された任意科目で置き換わる危険があり、個別必修確認を省略できない。

### 5.3 第4年次進級

根拠は工学部規程細則第10条第2号（冊子24頁／PDF28頁）と別表第1（冊子26頁／PDF30頁）の知能情報システムプログラム行・備考である。

| 区分 | 最低単位 | 現行実装 |
| --- | ---: | --- |
| 在学期間 | 3年 | MVP仮定または入力で評価 |
| 専門基礎A | 0 | 一致 |
| 専門基礎B | 10 | 一致 |
| 専門応用A | 19 | 一致 |
| 専門応用B | 26 | 一致 |
| 専門応用B/C/Eから | 11 | 最低枠配賦後の残余として実装 |
| 学部専門系計 | 66 | 一致 |
| 教養系計 | 32 | 一致 |
| 専門または教養 | 6 | 各区分最低超過分の合計として実装 |
| 総計 | 104 | 一致 |

備考による算入規則:

- E科目は6単位まで算入できる。
- D科目は算入できない。
- 専門基礎Bの10単位を超えた分は専門応用Bへ算入できる。
- 3年次編入学生には別基準がある。MVPは通常入学・編入なしを前提とするため対象外とし、将来は別`entry_route`プロファイルにする。

現行の数値、E上限、D除外、専門基礎B余剰の振替は公式表に一致する。ただし、評価器の残余配賦は科目単位の割当てではなく合計値の引算であり、現在と同じ単純な包含関係を持つ規則に限って妥当である。

### 5.4 卒業資格

根拠は工学部規程第8条・第16条、工学部規程細則第11条、別表第2（冊子27頁／PDF31頁）の知能情報システムプログラム行・備考である。

| 区分 | 最低単位 | 現行実装 |
| --- | ---: | --- |
| 在学期間 | 4年 | MVP仮定または入力で評価 |
| 専門基礎A | 0 | 一致 |
| 専門基礎B | 10 | 一致 |
| 専門応用A | 27 | 合計だけを評価。個別必修は未接続 |
| 専門応用B | 28 | 一致 |
| 専門応用B/C/D/Eから | 17 | 最低枠配賦後の残余として実装 |
| 学部専門系計 | 82 | 一致 |
| 教養系計 | 36 | 一致 |
| 専門または教養 | 6 | 各区分最低超過分の合計として実装 |
| 総計 | 124 | 一致 |

備考による算入規則:

- 卒業資格ではE科目単位数の上限を定めない。
- 専門基礎Bの10単位を超えた分は専門応用Bへ算入できる。
- 卒業時の追加枠はB/C/D/Eを対象とする。

現行は個別必修、同等科目、科目改廃、再履修の確認が未実装であるため、卒業の総合結果を`unknown`に固定している。この扱いは安全側である。

### 5.5 他プログラム科目

工学部規程細則第12条（冊子24頁／PDF28頁）は、所属プログラム以外のA/B/C科目を、原則として所属プログラムの専門応用Cとして加えられると定める。例外として、他プログラムの専門基礎科目が所属プログラム開設科目と同一科目名なら、所属プログラム側が定める専門基礎区分として扱う。

現行はこの読替えを明示実装していない。CSV側ですでに所属学生向け区分へ変換済みかも確認できていないため、次を確認するまで推測でCへ変換しない。

- CSVの科目区分が開講元区分か、所属学生向け認定後区分か
- 同一科目名の判定に開講番号を使えるか
- 読替え済み・認定済みを示す列や表記

## 6. 第2年次進級の確定規則

根拠は工学部規程細則第10条第1号（冊子23–24頁／PDF27–28頁）である。

1. 工学部に通算1年以上在学する。
2. 教養系科目と学部専門系科目を合計32単位以上修得する。
3. 総合工学概論、総合技術科学演習、技術者の心がまえ、知的財産概論、情報セキュリティ概論の5科目から合計4単位以上修得する。
4. D科目は32単位へ含めない。

現行の条件と一致する。夜間主科目、留学生代替、他プログラム科目など横断的な例外は別途適用が必要である。

| 修得時点 | 細則第10条、冊子24頁／PDF28頁 | 第4年次進級は第3年次終了までに修得した単位で判定する。 | 評価器は取得年度・学期を条件へ使わない。通常の1–3年生CSVでは将来単位がない前提だが、任意時点評価には不足。 |
| 科目同一性 | 標準課程表、第12条 | 同名、名称変更、再履修、他プログラム同名科目を区別する必要がある。 | 開講番号がなければ科目名を同一性に使うため未確定。 |

これらは資料に規則があるが、CSV入力だけでは必要情報が足りない場合がある。入力不足時は0単位や不合格へ変換せず、該当し得る科目が結果へ影響するとき`unknown`とする。

## 9. 規則エンジンの拡張性監査

現在のプロファイル追加方式は、「教養／専門」「専門基礎／専門応用」「A–E」「第2／第4年次進級／卒業」という同じ制度を共有する範囲では利用できる。制度が異なる分野へ広げる場合、次の制約がある。

1. 要件IDと学年別表示がPythonに固定され、プロファイルへ新しい進級節目を追加しても自動評価されない。
2. 教養／専門、基礎／応用、A–EがスキーマとPythonの固定列挙である。
3. `allocation_rules`は検証・表示用で、評価器は実行しない。実際の上限・除外・残余は各conditionへ重複して記載されている。
4. 残余配賦は科目ごとの割当てではなく合計値の引算であり、重なる枠、複数の振替先、選択可能な配賦順序を一般には扱えない。
5. 科目マスターを読み込む機能はあるが、CSV評価経路へ接続されていない。
6. selectorの未知キーや値型を十分検証せず、誤記した条件が無視される可能性がある。
7. prefix分類は複数一致の曖昧性を検出せず、CSV別名と公式の正規区分が一体化している。
8. 科目同一性が開講番号、なければ科目名だけであり、履修試行、同等科目、読替えを分けられない。
9. 入学区分、留学生区分、判定時点等の適用条件をプロファイルで表現できない。
10. 第4年次進級と卒業に教養条件が複製され、片方だけ修正する危険がある。

将来の規則データは、少なくとも次へ分ける。

- `scope`: 大学・学部・プログラムの安定ID、入学年度、規則改訂、入学区分
- `sources` / `decisions`: 資料、頁、表、行、列、注記、セル範囲、解釈、確度
- `taxonomy`: その学部固有の区分軸と許容値
- `category_mappings`: CSV原値・別名から正規区分への写像
- `course_catalog`: canonical course ID、開講番号、別名、同等科目、適用年度、単位、区分
- `credit_pools`: 再利用できる単位集合
- `allocations`: 優先順位、上限、除外、余剰の行先を持つ科目単位の一回限り配賦
- `requirements`: 適用学年・判定時点・学生属性と条件

大学共通、学部共通、プログラム固有、入学年度差分を別ファイルとして合成し、合成後の解決済みプロファイルを厳格検証する構成が望ましい。

## 10. 他年度・他分野を追加するときの確認手順

1. 対象年度の公式資料URL、版、取得日、適用対象を固定する。
2. 大学規則、学部規程、細則、最低単位表、プログラム科目表、標準課程表、履修上の注意を全て列挙する。
3. 冊子頁とPDF頁を併記し、表は行・列・備考・結合セルの開始／終了を確認する。
4. 大学共通、学部共通、分野共通、プログラム固有、入学年度固有の規則へ分離する。
5. 必修、選択必修、選択という表示語をCSVの同名列へ直接対応させず、公式の科目区分と配賦規則を確認する。
6. 最低枠、合計枠、共通枠、上限、除外、余剰振替、二重計上禁止を配賦順序として記録する。
7. 個別必修、all-of／one-of、同等科目、名称変更、再履修、他プログラム読替えを科目マスターへ記録する。
8. 編入、再入学、留学生、早期卒業等の例外を、通常学生の規則へ暗黙に混ぜない。
9. CSVだけで必要情報を得られない規則は、入力追加または`unknown`条件として明示する。
10. 別担当者が公式資料と独立照合し、`verified`へ変更する。
11. 既存年度を上書きせず、新しい版として追加する。

## 11. 必須テスト一覧

### 11.1 公式規則への適合

- 各conditionとallocationに根拠参照があること
- 公式表から独立転記した適合表とプロファイルが一致すること
- 全最低値について`minimum - 1`、`minimum`、`minimum + 1`
- 追加の有効単位で判定が悪化しないこと
- 配賦済み単位合計が対象となる一意な確認済み単位を超えないこと
- 入力科目順を変えても結果が変わらないこと

### 11.2 教養

- 自然科学だけで10
- 自然系共通専門基礎6 + 自然科学4
- 必修指定以外の情報リテラシー2 + 自然科学8
- 対象3区分の合計9で不足
- 対象3区分の合計12を、選択必修10 + 選択残余2へ配賦
- データサイエンス入門を必修2と選択必修10へ二重計上しない
- 人文社会4を必修へ、新潟大学個性化科目2を選択必修へ配賦
- 健康スポーツ科学実習Ⅰ／Ⅱの必修差
- 英語基礎L/Rを人文社会・教育科学へ分類
- 夜間主科目を全要件から除外
- 留学生代替は必要属性や内容が不明なら`unknown`

### 11.3 専門

- 専門基礎Bの10未満、10、10超過
- 基礎B余剰を応用Bへ一度だけ振り替える
- 第4年次進級のEを6で上限化し、Dを除外
- 卒業のEに上限を付けず、Dを追加17枠へ含める
- 応用B最低枠とB/C/D/E追加枠の二重計上防止
- 他プログラムA/B/Cを応用Cへ読替え
- 他プログラムの同名専門基礎科目を所属プログラム区分へ読替え
- A合計27を満たしても正規A科目に欠落があれば卒業を充足にしない

### 11.4 拡張性

- 新しい要件IDと非A–E体系の架空プロファイルをPython変更なしで列挙・評価できること
- 曖昧なprefix／aliasをエラーまたは`unknown`にすること
- 未知のselectorキーと不正な型をプロファイル読込み時に拒否すること
- all-of、one-of、同等科目、再履修、判定時点をテストすること
- 複数プロファイルを連続評価して状態が混ざらないこと

## 12. 今回の結論

数値上の第2・第4年次進級、卒業の専門区分と合計は、現行プロファイルと公式資料で一致した。教養では、人文社会／個性化科目の2単位枠と選択残余方式は一致する一方、選択必修10単位の対象を誤って狭く実装している。

さらに、大学学習法の所属分野指定、夜間主科目、留学生代替、非専門科目の教養扱い、他プログラム科目のC読替え、正規科目マスターと判定時点は、現行集計で未対応または入力不足である。これらを解消するまでは、該当可能性のある入力について確定的な合格／不合格を返さない。

照合はNFKC正規化と空白除去で全半角、ローマ数字、空白差を吸収する。科目名の一般的な部分一致は用いず、プログラミングＡⅠとＡⅡ等を区別する。明示別名の衝突と別プロファイルのマスター流用は拒否する。

## 14. 卒業の個別必修確認の実装

利用者の「個別必修確認を実装してほしい」という依頼により、既存科目マスターを卒業評価へ接続した。根拠は第13節で転記した工学科共通のA科目（冊子8頁／PDF12頁）と知能情報システムのA科目（冊子12頁／PDF16頁）、標準課程表A列（冊子39頁／PDF43頁）であり、学務規則そのものの変更ではない。

### 14.1 判定方法

- `individual_required_courses`条件を`kind="required_courses"`として追加する。
- 当該プロファイルの科目マスターで`required_for`に`graduation`を含む16科目を読み込む。Pythonへ科目名や件数を固定しない。
- 科目名・明示別名を照合し、算入可能な専門系A科目について、合格かつ必要単位以上の修得行が確認できた科目を`satisfied`とする。
- 行が存在しない、不合格のみ、確認済み単位が必要単位未満なら`not_satisfied`。合否・単位・分類が未確定で結論が変わり得る場合は`unknown`とする。
- 既存の単位集計では異コードの同名行を別科目として扱う。個別必修確認では1つの必修の修得確認を重ねても、別の必修の代替にしない。必要単位未満の複数修得行を足して1科目修得とはしない。
- 同一開講番号に異なる必修名が付く不整合入力は、その番号から複数科目の充足を確定せず`unknown`候補とする。
- 個別確認の単位は説明専用で、区分計・総計・残余配賦へ再加算しない。

### 14.2 API・画面・総合判定

条件は修得確認済み件数、未修得科目名、判定不能科目名、および全必修の科目別結果・理由・根拠頁を返す。画面の「専門系の個別必修科目」から科目別一覧を開ける。

個別必修の未実装による卒業の`blocked`状態を解除し、`partial`とした。根拠データの`transcribed`状態は保持しつつ、全条件充足なら卒業総合`satisfied`、確定した未充足があれば`not_satisfied`、それ以外に未確定情報が影響すれば`unknown`とする。

### 14.3 検証

- 公開科目名と架空の開講番号・成績だけを使い、単体・APIの139テストが成功。
- 全必修16科目修得、総計124単位で卒業`satisfied`。
- 別コードの同名A科目でA合計27・総計124を保っても、別の必修を欠落させれば卒業`not_satisfied`。
- 必修1科目の合否または単位数が未確定なら、その科目と必要な集計へ`unknown`を伝播。
- 空の必修一覧、マスター未指定、必修の必要単位不明・0を設定エラーとして拒否。
- 手動確認用に`examples/graduation-sample.csv`を用意し、同じファイルをAPI回帰テストから使用する。
